🔄 How a Single Page Application (SPA) Works

Traditional websites reload the whole page on every click. A SPA loads once — Angular intercepts navigation, swaps components, and updates the URL, without a full reload.

TypeScript Essentials for Angular

You don't need to master TypeScript — but you need these 10 concepts to read Angular code.

TypesInterfaces ClassesDecorators Genericsasync/await
Why TypeScript? JavaScript lets you write let x = 5; x = "hello" with no error. That kind of surprise causes bugs that only appear at runtime — when real users are using your app. TypeScript adds a type-checking layer at development time, catching those mistakes in your editor before you ever run the code. Angular requires TypeScript because large apps become unmaintainable without it — you can refactor with confidence, hover over any symbol to see what it contains, and auto-complete saves enormous amounts of time.
  • Plain JavaScript → finds errors at runtime (production crashes)
  • TypeScript → finds errors at compile time (caught in your editor)
  • TypeScript compiles down to plain JavaScript — browsers never see the TypeScript

📦 Types & Interfaces

// Types — restrict what values a variable can hold
let name: string = 'Alice';
let age: number = 30;
let isAdmin: boolean = false;
let items: string[] = ['a', 'b'];    // array of strings
let data: any = 'anything';           // avoid — disables type checking

// Union — can be one of several types
let id: string | number = 42;

// Interface — describes the shape of an object
interface Product {
  id: string;
  name: string;
  price: number;
  imageUrl?: string;   // ? means optional
}

// Type alias — another way to describe shapes
type Status = 'pending' | 'paid' | 'shipped';  // union of literals

🏛️ Classes

class CartService {
  // Properties with access modifiers
  private items: Product[] = [];
  readonly maxItems = 99;   // can read, never re-assign

  // Constructor — runs when class is instantiated
  constructor(private storageKey: string) {
    // 'private storageKey' declares AND assigns the property in one step
  }

  // Method
  addItem(product: Product): void {
    this.items.push(product);
  }

  // Getter — accessed like a property: service.total
  get total(): number {
    return this.items.reduce((sum, p) => sum + p.price, 0);
  }
}

Angular CLI & Project Setup

The CLI generates code, runs your dev server, builds, tests, and lints — all from the terminal.

What the CLI really does Without the CLI you'd have to manually configure TypeScript, webpack, test runners, linters, polyfills, and a development server — a multi-day setup. The CLI handles all of that invisibly. When you run ng generate component it doesn't just make a file — it creates the .ts, .html, .css and .spec.ts files all wired together with the correct boilerplate. ng build produces a production bundle with tree-shaking (removes unused code), minification, and code-splitting for lazy routes — all zero-configuration.

Module 03

Components — The Building Blocks

Every piece of UI is a component. Master this and you've mastered 60% of Angular.

@Component decorator@Input / @Output @ViewChildChangeDetection Content Projection basics
What is a Component — really? A component is a custom HTML element. You define <app-product-card> once, then use it anywhere like a native HTML tag. Under the hood it has three parts working together:

Template (HTML) — describes what to show on screen.
Class (TypeScript) — holds data and methods. The "brain" of the component.
Metadata (@Component decorator) — tells Angular how to wire the template and class together.

Components are the only way to create UI in Angular. Everything you see on screen — navbars, buttons, forms, pages — is a component.

🧱 Anatomy of a Component

// Every component is a TypeScript class + @Component decorator
import { Component, Input, Output, EventEmitter, inject } from '@angular/core';
import { CommonModule } from '@angular/common';
import { RouterLink } from '@angular/router';

@Component({
  selector: 'app-product-card', // the HTML tag: <app-product-card>
  standalone: true,             // modern Angular — no NgModule needed
  imports: [CommonModule, RouterLink], // declare what THIS component uses
  template: `                  // inline HTML template
    <div class="card">
      <img [src]="product.imageUrl" [alt]="product.name" />
      <h3>{{ product.name }}</h3>
      <p>{{ product.price | currency }}</p>
      <button (click)="onAddToCart()">Add to Cart</button>
    </div>
  `,
  // styleUrls: ['./product-card.component.css']  — or use styles: []
})
export class ProductCardComponent {
  @Input() product!: Product;            // data received from parent
  @Output() cartAdded = new EventEmitter<Product>(); // event sent to parent

  private cart = inject(CartService);   // get service via DI

  onAddToCart(): void {
    this.cart.addItem(this.product);
    this.cartAdded.emit(this.product);   // notify parent
  }
}

/>

// PARENT class

  console.log('Added:', product.name);

@Component({

🚀 ChangeDetectionStrategy.OnPush — Performance

import { Component, ChangeDetectionStrategy, Input } from '@angular/core';

@Component({
  selector: 'app-product-card',
  changeDetection: ChangeDetectionStrategy.OnPush,
  // ↑ Only re-render when:
  //   1. An @Input reference changes
  //   2. An event originates from this component
  //   3. An Observable/Signal this component uses emits
  // Default strategy re-checks on EVERY event anywhere in the app.
  template: `...`

export class ProductCardComponent {}
🎯 Use OnPush on "dumb" components (components that only display data via @Input). This is a free performance win — Angular skips checking them unless their inputs change.

📤 New Signal-Based Inputs (Angular 17+)

import { Component, input, output } from '@angular/core';

export class ProductCardComponent {
  // Signal inputs — replace @Input decorator
  product  = input.required<Product>();       // required
  showBadge = input<boolean>(false);          // with default

  // Signal outputs — replace @Output + EventEmitter
  cartAdded = output<Product>();

  // Read input like a signal: this.product()
  onAdd() {
    this.cartAdded.emit(this.product());
  }
}

Module 04

Templates & Data Binding

Templates are HTML + Angular superpowers. Master the four binding types and you can build any UI.

The golden rule of Angular templates Data in a component class can only reach the HTML in four ways. Once you know these four, you can read any Angular template:
  • {{ }} — Interpolation. Class → screen. Read-only display of values.
  • [property] — Property binding. Class → element property. Sets attributes, styles, disabled states.
  • (event) — Event binding. User action → class method. Captures clicks, input, keypresses.
  • [(ngModel)] — Two-way binding. Value flows both directions. Used in form inputs so the class and the input stay in sync automatically.
The bracket/parenthesis pattern is intentional: [receives] something, (gives) something, [(banana-in-a-box)] does both.

🔗 The Four Binding Types

Interpolation{{ value }}Class → Template<h1>{{ title }}</h1>
Property Binding[property]="expr"Class → Template<img [src]="url">
Event Binding(event)="handler()"Template → Class<button (click)="save()">
Two-Way Binding[(ngModel)]="prop"Both directions<input [(ngModel)]="name">

<p>Total: {{ price * quantity }}</p>       <!-- expressions work -->
<p>{{ user?.name ?? 'Guest' }}</p>         <!-- optional chaining works -->

<!-- Property binding — sets element properties -->

Module 05

Directives

Directives add behaviour to existing elements without creating new components.

Structural Directives Attribute Directives Custom Directives
Directives vs Components — what's the difference? A Component has a template — it adds new HTML to the page (like <app-button>). A Directive has no template — it enhances an existing HTML element with new behaviour (like making any element close a dropdown when you click outside it). Think of it this way: a component is a new LEGO piece, a directive is a sticker you put on an existing piece to give it a new power. There are two kinds:
  • Attribute directives — change the appearance or behaviour of an element. e.g. ngClass, ngStyle, custom clickOutside
  • Structural directives — add or remove elements from the DOM. e.g. *ngIf, *ngFor

🎨 Attribute Directives — ngClass, ngStyle

<!-- ngClass — add/remove CSS classes dynamically -->
<div [ngClass]="'active'">always has 'active' class</div>
<div [ngClass]="{ active: isActive, disabled: isDisabled }">conditional</div>
<div [ngClass]="['btn', isPrimary ? 'btn-primary' : 'btn-secondary']"></div>

<!-- ngStyle — add inline styles dynamically -->
<div [ngStyle]="{ color: textColor, 'font-size.px': fontSize }"></div>

<!-- Modern shorthand (no NgClass needed) -->
<div
  [class.active]="isActive"
  [class.disabled]="isDisabled"
  [style.color]="textColor"
  [style.fontSize.px]="fontSize"
></div>

🛠️ Custom Attribute Directive — ClickOutside (from BlossomRays)

import { Directive, ElementRef, HostListener, Output, EventEmitter, inject } from '@angular/core';

@Directive({
  selector: '[clickOutside]',   // applied as an attribute: <div clickOutside>
  standalone: true,
})
export class ClickOutsideDirective {
  private el = inject(ElementRef);
  @Output() clickedOutside = new EventEmitter<void>();

  // @HostListener — listen to events on the HOST element or global
  @HostListener('document:click', ['$event.target'])
  onDocumentClick(target: HTMLElement): void {
    const isInside = this.el.nativeElement.contains(target);
    if (!isInside) this.clickedOutside.emit();
  }
}

<!-- Usage in template -->
<div clickOutside (clickedOutside)="closeMenu()">
  <!-- clicks outside this div fire closeMenu() -->
</div>

🏗️ Custom Structural Directive (Advanced)

import { Directive, Input, TemplateRef, ViewContainerRef } from '@angular/core';

// Behaves like *ngIf but checks user role
@Directive({ selector: '[hasRole]', standalone: true })
export class HasRoleDirective {
  private vcr = inject(ViewContainerRef);
  private tmpl = inject(TemplateRef);

    this.vcr.clear();

  }
}

Module 06

Pipes — Transform Data In Templates

Pipes format values in templates without modifying the original data.

What pipes do and why they exist Imagine you have a product price stored as the integer 4999 (pence). You need to display it as "£49.99" on screen. You could call a format function every time — but that clutters the template. A pipe keeps the original data untouched and transforms it purely for display purposes. The key idea: pipes are display transformers only. They never mutate the underlying data.

The syntax {{ value | pipeName:arg1:arg2 }} reads as: "show value, but pass it through pipeName with these arguments first".

🔧 Built-In Pipes

<!-- Currency -->
{{ 4999 | currency }}                    <!-- $4,999.00 -->
{{ 4999 | currency:'GBP':'symbol':'1.0-0' }} <!-- £4,999 -->

<!-- Date -->
{{ order.createdAt | date }}             <!-- Jul 27, 2026 -->
{{ order.createdAt | date:'dd/MM/yyyy' }} <!-- 27/07/2026 -->
{{ order.createdAt | date:'shortTime' }} <!-- 3:45 PM -->

<!-- String -->
{{ 'hello world' | uppercase }}          <!-- HELLO WORLD -->
{{ 'HELLO' | lowercase }}                <!-- hello -->
{{ 'hello world' | titlecase }}          <!-- Hello World -->
{{ longText | slice:0:100 }}             <!-- first 100 chars -->

<!-- Number -->
{{ 3.14159 | number:'1.2-2' }}           <!-- 3.14 (min 1 int, 2 decimals) -->

<!-- JSON (useful for debugging) -->
{{ myObject | json }}

<!-- Async pipe — unwraps Observable/Promise -->
{{ user$ | async }}                      <!-- subscribes and auto-unsubscribes -->
<div *ngIf="products$ | async as products">
  {{ products.length }} products
</div>

<!-- Pipe chaining -->
{{ product.name | uppercase | slice:0:20 }}

🎨 Custom Pipe — FormatPrice (from BlossomRays)

import { Pipe, PipeTransform } from '@angular/core';

@Pipe({
  name: 'formatPrice',   // how you call it in templates
  standalone: true,
  pure: true,            // default — only re-runs when INPUT changes (fast)
})
export class FormatPricePipe implements PipeTransform {
  transform(cents: number): string {
    return new Intl.NumberFormat('en-GB', {
      style: 'currency', currency: 'GBP'
    }).format(cents / 100);
  }
}

<!-- Usage -->
{{ product.price | formatPrice }}        <!-- £29.99 -->
Pure Pipes default
Re-runs only when the input value/reference changes. Fast. Angular can cache results. Use for formatting, calculations.
Impure Pipes careful
Re-runs on every change detection cycle. Slow. Use only when the pipe depends on external state (e.g. current time). Set pure: false.
Module 07

Services & Dependency Injection

Services hold shared logic and data. DI is how Angular hands services to whoever needs them.

Why not just put everything in the component? You could put your HTTP calls, cart logic, and user state directly in a component — and many beginners do. The problem: when three different components all need the cart data, you'd have to duplicate the logic. If the cart changes in one place, the others wouldn't know. Services solve this by being a single source of truth that any component can share. Angular creates the service once (a singleton) and hands the same instance to every component that asks for it via Dependency Injection. This means one cart, one auth state, one product list — everywhere in the app.

💡 What Is a Service?

A service is a TypeScript class that:

  • Holds data that multiple components share (e.g. cart items)
  • Wraps HTTP calls (e.g. ProductService.getProducts())
  • Contains business logic that doesn't belong in a component
  • Is created once and shared across the entire app

⚙️ Creating a Service

import { Injectable, inject } from '@angular/core';

@Injectable({
  providedIn: 'root',
  // ↑ Angular creates ONE instance and makes it available app-wide.
  //   This is "tree-shakeable" — if nothing injects this service,
  //   it's excluded from the bundle entirely.
})
export class ProductService {
  private supabase = inject(SupabaseService).client;

  async getProducts(category?: string): Promise<Product[]> {
    let query = this.supabase
      .from('products')
      .select('*')
      .eq('active', true);

    if (category) query = query.eq('category', category);

    const { data } = await query;
    return data ?? [];
  }
}

🪙 InjectionToken — For Non-Class Values

import { InjectionToken, inject } from '@angular/core';

// Use InjectionToken when you want to inject a non-class value (config, string, etc.)
export interface AppConfig {
  apiUrl: string;
  maxCartItems: number;
}

export const APP_CONFIG = new InjectionToken<AppConfig>('app.config', {
  factory: () => ({ apiUrl: '/api', maxCartItems: 99 }),
});

// Inject anywhere
const config = inject(APP_CONFIG);
console.log(config.apiUrl);  // '/api'

// Override per component (e.g. in tests):
@Component({
  providers: [{ provide: APP_CONFIG, useValue: { apiUrl: '/mock', maxCartItems: 5 } }]
})

🏭 All DI Provider Patterns

// 1. useClass — provide a DIFFERENT class for the same token
{ provide: LoggerService, useClass: ProductionLoggerService }

// 2. useValue — provide a literal value
{ provide: API_URL, useValue: 'https://api.example.com' }

// 3. useFactory — compute the value at runtime
{ provide: ANALYTICS, useFactory: (env: Environment) => new Analytics(env.key),
  deps: [Environment] }

// 4. useExisting — alias one token to another
{ provide: OldService, useExisting: NewService }

// 5. multi — collect multiple values under one token

Routing — Navigation Between Pages

The router maps URLs to components and manages navigation without page reloads.

What routing does and why lazy loading matters Without a router, a URL change would reload the entire page from the server. Angular's router intercepts URL changes and swaps the content on screen — no server round-trip. This is what makes navigation feel instant.

Lazy loading means each page's JavaScript is in its own separate file and is only downloaded when the user first visits that page. Without it, your entire app would be bundled into one huge file and the user would wait for ALL of it to download before seeing anything — even pages they may never visit. BlossomRays uses loadComponent() for every page, so the admin bundle is never downloaded by regular customers.

Forms — Template-Driven & Reactive

Angular has two form systems. Know when to use each one.

Which form approach should you use? Angular gives you two completely different ways to build forms. They look similar on screen but work very differently under the hood:
  • Template-Driven: You write the form logic inside HTML with ngModel. Angular generates the form model automatically. Simple to write but hard to test and hard to control. Use for simple 2-3 field forms.
  • Reactive: You define the form structure explicitly in TypeScript using FormBuilder. More setup but you have total control. Validation logic lives in the class, not the template. Easier to unit test. Use for any form that's more than trivial — BlossomRays uses this for checkout and registration.
The rule of thumb: if you can feel it getting complicated, switch to Reactive Forms.

HTTP Client

Angular's built-in HTTP client for talking to APIs. Returns Observables by default.

HttpClient vs the browser's fetch — why Angular has its own? The browser has a built-in fetch() API. Angular's HttpClient wraps that with important extras:
  • Returns Observables — you can cancel a request mid-flight (e.g. user types a new search before the previous results arrive), retry automatically, or transform the stream with RxJS operators.
  • Typed responses — http.get<Product[]>('/api/products') gives you a typed result. TypeScript knows the shape.
  • Interceptors — middleware that runs on every request/response. BlossomRays uses one to automatically add the Supabase auth token to every request.
  • Easy testing — Angular provides HttpClientTestingModule to mock all HTTP calls in unit tests.

🌐 Making HTTP Requests

import { HttpClient, HttpHeaders, HttpParams } from '@angular/common/http';
import { firstValueFrom } from 'rxjs';

export class ApiService {
  private http = inject(HttpClient);

  // GET — basic
  getProducts() {
    return this.http.get<Product[]>('/api/products');  // Observable
  }

  // GET with params (?category=perfume&page=1)
  searchProducts(category: string) {
    const params = new HttpParams()
      .set('category', category)
      .set('page', '1');
    return this.http.get<Product[]>('/api/products', { params });
  }

  // POST — send data
  createOrder(order: OrderRequest) {
    return this.http.post<Order>('/api/orders', order);
  }

  // PATCH — partial update
  updateOrderStatus(id: string, status: string) {
    return this.http.patch<Order>(`/api/orders/${id}`, { status });
  }

  // Convert Observable → Promise (useful with async/await)
  async checkout(items: CartItem[]) {
    const result = await firstValueFrom(
      this.http.post<{ url: string }>('/api/stripe/checkout', { items })
    );
    window.location.href = result.url;
  }
}

import { HttpInterceptorFn } from '@angular/common/http';
import { from, switchMap } from 'rxjs';

// An interceptor = middleware for every HttpClient request/response
export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const supabase = inject(SupabaseService);
  return from(supabase.client.auth.getSession()).pipe(
    switchMap(({ data }) => {
      if (!data.session?.access_token) return next(req);
      const authReq = req.clone({               // HttpRequest is IMMUTABLE
        setHeaders: { Authorization: `Bearer ${data.session.access_token}` }
      });
      return next(authReq);
    })
  );
};

// Error-handling interceptor
export const errorInterceptor: HttpInterceptorFn = (req, next) => {
  return next(req).pipe(
    catchError((error: HttpErrorResponse) => {
      if (error.status === 500) toastService.error('Server error, try again');
      return throwError(() => error);
    })
  );
};

Signals — Modern Reactive State

Angular's built-in reactivity system. Simpler than RxJS for most state management tasks.

signal()computed() effect()input() / output() linkedSignalresource()
The problem signals solve — and what came before Before signals, Angular used Zone.js — a library that patches browser APIs like setTimeout, addEventListener, and HTTP responses to detect when anything happened, then checked the entire component tree for changes. Imagine a store with 200 products — every button click triggered Angular to inspect all 200 cards, every service, every pipe. Inefficient.

A signal is a value Angular tracks precisely. When cartItems changes, only the components that actually read cartItems() update. Nothing else is touched. It's the difference between a smoke alarm going off in one room vs. every alarm in the building triggering at once.

⚡ The Three Core Primitives

import { signal, computed, effect } from '@angular/core';

// signal() — writable reactive state
const count = signal(0);
count();              // READ: returns 0
count.set(5);         // WRITE: set to 5
count.update(n => n + 1);  // UPDATE based on current value
count.mutate(arr => arr.push(item));  // MUTATE in-place (arrays/objects)

// computed() — derived, read-only signal
const doubleCount = computed(() => count() * 2);
doubleCount();  // 10 — auto-recalculates only when count() changes

// effect() — run code when signals change
effect(() => {
  // runs when any signal read inside this function changes
  console.log('Count changed to:', count());
  localStorage.setItem('count', String(count()));
});

🛒 Real Example — CartService with Signals

@Injectable({ providedIn: 'root' })
export class CartService {
  readonly items      = signal<CartItem[]>(this._load());

  // Derived signals — auto-update when items changes
  readonly totalItems = computed(() =>
    this.items().reduce((sum, i) => sum + i.quantity, 0));
  readonly subtotal   = computed(() =>
    this.items().reduce((sum, i) => sum + i.product.price * i.quantity, 0));
  readonly isEmpty    = computed(() => this.items().length === 0);

  constructor() {
    // Persist to localStorage whenever cart changes
    effect(() => {
      localStorage.setItem('cart', JSON.stringify(this.items()));
    });
  }

  addItem(product: Product, qty = 1) {
    this.items.update(current => {
      const existing = current.find(i => i.product.id === product.id);
      if (existing) return current.map(i =>
        i.product.id === product.id ? { ...i, quantity: i.quantity + qty } : i
      );
      return [...current, { product, quantity: qty }];
    });
  }
}

RxJS Essentials

Reactive programming with Observables. You need these 15 operators for Angular.

Observable vs Promise — why two different async tools? A Promise delivers one value once and is done. A Observable is a stream that can deliver zero, one, or many values over time, and can be cancelled. Think of it like this:
  • Promise = a taxi. You order it, it arrives once, journey over.
  • Observable = a bus route. Multiple passengers (subscribers), runs on a schedule, you can get on or off, the route can be cancelled.
For a single HTTP call, both work fine. But for a search box (emitting values as the user types, cancelling previous searches), websocket messages, or combining data from multiple sources, Observables are essential. Angular's HttpClient returns Observables because it gives you the option to cancel. The async pipe in templates subscribes and unsubscribes automatically when the component is destroyed — preventing memory leaks.

🌊 Observable Basics

import { Observable, Subject, BehaviorSubject, of, from, interval } from 'rxjs';

// Observable — a stream of values over time
const numbers$ = new Observable<number>(observer => {
  observer.next(1);  // emit a value
  observer.next(2);
  observer.complete(); // done
});
const sub = numbers$.subscribe({
  next: v => console.log(v),  // 1, 2
  error: e => console.error(e),
  complete: () => console.log('done'),
});
sub.unsubscribe();  // stop listening (prevent memory leaks)

// Helper creation functions
of(1, 2, 3);              // emits 1, 2, 3 then completes
from([1, 2, 3]);          // same, from array
from(Promise.resolve('hi')); // wraps a Promise
interval(1000);            // emits 0,1,2... every 1 second

const clicked$ = new Subject<Event>();

clicked$.subscribe(e => ...);  // late subscribers miss past values

user$.next(loggedInUser);

user$.subscribe(u => ...);  // immediately gets current value, then future ones

🔧 The Most Important Operators

import {
  map, filter, tap, switchMap, mergeMap, concatMap, exhaustMap,
  catchError, debounceTime, distinctUntilChanged, takeUntilDestroyed,
  startWith, combineLatest, forkJoin, retry
} from 'rxjs/operators';

// map — transform each value
numbers$.pipe(map(n => n * 2));   // 2, 4, 6

// filter — only pass through values that match
numbers$.pipe(filter(n => n > 1)); // 2, 3

// tap — side effect without changing the stream
numbers$.pipe(tap(n => console.log('Got:', n)));

// debounceTime — wait N ms after last emission (perfect for search)
searchInput$.pipe(debounceTime(300));

// distinctUntilChanged — skip if same value as last
searchInput$.pipe(distinctUntilChanged());

// switchMap — cancel previous inner Observable when new value arrives
// PERFECT for search: cancels previous HTTP call when user types again
searchQuery$.pipe(switchMap(q => http.get(`/search?q=${q}`)));

// mergeMap — run all inner Observables in PARALLEL
ids$.pipe(mergeMap(id => http.get(`/items/${id}`)));

// concatMap — run inner Observables one at a TIME (queue)
saveRequests$.pipe(concatMap(req => http.post('/save', req)));

// catchError — handle errors in the stream
api$.pipe(catchError(err => of({ error: err.message })));

// retry — retry on error N times
api$.pipe(retry(3));

// startWith — emit an initial value before the Observable starts
data$.pipe(startWith(null));  // useful for loading states

// forkJoin — wait for ALL Observables to complete, emit combined result
forkJoin({ user: getUser$, orders: getOrders$ }).subscribe(({ user, orders }) => ...);

// combineLatest — emit latest from ALL when ANY emits
combineLatest([category$, sort$]).pipe(switchMap(([cat, sort]) => fetchProducts(cat, sort)));

// takeUntilDestroyed — auto-unsubscribe when component destroys (Angular 16+)
private destroyRef = inject(DestroyRef);
route.params.pipe(takeUntilDestroyed(this.destroyRef)).subscribe(...);

🔍 Debounced Search — Classic RxJS Pattern

export class NavbarComponent {
  private searchSubject = new Subject<string>();

  // Build the search results Observable
  results$ = this.searchSubject.pipe(
    debounceTime(300),           // wait 300ms after last keystroke
    distinctUntilChanged(),      // don't re-search same term
    switchMap(term =>            // cancel previous request on new term
      term.length < 2
        ? of([])                  // don't search for 1 char
        : this.productService.search(term).pipe(
            catchError(() => of([]))  // return empty on error
          )
    ),
    startWith([])               // initial value
  );

  // In template: <div *ngFor="let r of results$ | async">{{ r.name }}</div>

  onSearch(term: string) {
    this.searchSubject.next(term);
  }
}

    if (changes['product']) {

Change Detection

How Angular knows when to update the DOM. Understanding this prevents bugs and performance issues.

How Angular knows the screen needs updating Angular needs to know when data changes so it can update the DOM. It does this through change detection — a process where Angular compares the current data to the previous data and updates any part of the HTML that changed. Zone.js (the default) triggers this check automatically after any browser event — clicks, keypresses, HTTP responses, timers. The problem: every event causes Angular to walk the entire component tree and check everything. In a large app this can run hundreds of checks per second.

OnPush tells Angular: "only check this component when its inputs actually change or a signal/observable it uses emits". For components that only display data passed in via @Input — like ProductCardComponent — this is a free performance win.

🔄 Default vs OnPush Strategy

Default Strategy

@Component({
  // No changeDetection specified = Default
  template: `{{ name }}`
})
export class MyComp {
  name = 'Alice';
}
// Angular checks this component on:
// • Every click/keypress anywhere in the app
// • Every HTTP response
// • Any setTimeout/setInterval
// → Potentially checks HUNDREDS of components per event

OnPush Strategy

@Component({
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `{{ product.name }}`
})
export class ProductCard {
  @Input() product!: Product;
}
// Angular ONLY checks this component when:
// • An @Input reference changes
// • An event fires FROM this component
// • A signal/async pipe inside it emits
// → Much faster for "dumb" display components

⚠️ Common Mutation Bug with OnPush

// ❌ WRONG — mutating the array doesn't change its reference
// OnPush component won't re-render!
this.items.push(newItem);      // same array reference
this.items[0].name = 'Bob';   // same object reference

// ✅ CORRECT — create a NEW reference
this.items = [...this.items, newItem];      // new array
this.items = this.items.map((item, i) =>
  i === 0 ? { ...item, name: 'Bob' } : item  // new object
);

// Signals solve this automatically — any .set()/.update() triggers CD
this.items.update(arr => [...arr, newItem]);  // always triggers

import { ChangeDetectorRef } from '@angular/core';

    // Called outside Angular's zone (e.g. from a 3rd party library)

    this.cdr.detach();            // stop automatic CD

Angular Animations

Define animations in TypeScript with Angular's animation DSL.

Angular Animations vs CSS transitions — when to use which CSS transitions and animations are fine for simple hover effects. Angular animations are better when:
  • The timing depends on data changes (e.g. animate when a product list appears based on an API response)
  • You need to animate elements being added or removed from the DOM (:enter / :leave) — CSS can't do this because the element doesn't exist before it enters
  • You need stagger — animating a list of items with sequential delays
  • The animation depends on component state (e.g. expand a panel when isOpen = true)
In BlossomRays, the product cards use stagger to fade in one by one after loading from Supabase. CSS can't do that because it doesn't know when the data arrives. 
import {
  trigger, state, style, animate, transition,
  query, stagger, group, sequence, keyframes
} from '@angular/animations';

@Component({
  animations: [
    // trigger() — names the animation, used in template as [@name]
    trigger('fadeInOut', [
      // state() — define styles for named states
      state('visible',  style({ opacity: 1, transform: 'translateY(0)' })),
      state('hidden',   style({ opacity: 0, transform: 'translateY(-10px)' })),

      // transition() — animate between states
      transition('visible => hidden', animate('200ms ease-in')),
      transition('hidden => visible',  animate('300ms ease-out')),

      // :enter / :leave — element added/removed from DOM
      transition(':enter', [
        style({ opacity: 0, transform: 'scale(0.9)' }),
        animate('200ms ease-out', style({ opacity: 1, transform: 'scale(1)' }))
      ]),
      transition(':leave', animate('150ms ease-in', style({ opacity: 0 }))),
    ]),

    // Stagger animation for lists (used in BlossomRays products page)
    trigger('listAnimation', [
      transition('* => *', [    // any value change
        query(':enter', [        // select entering children
          style({ opacity: 0, transform: 'translateY(16px)' }),
          stagger(40, [          // 40ms delay between each
            animate('300ms ease-out', style({ opacity: 1, transform: 'translateY(0)' }))
          ])
        ], { optional: true }),  // don't crash if no :enter elements
      ]),
    ]),

    // Keyframe animation (like CSS @keyframes)
    trigger('bounce', [
      transition(':enter', [
        animate('600ms', keyframes([
          style({ transform: 'translateY(0)',    offset: 0 }),
          style({ transform: 'translateY(-20px)', offset: 0.3 }),
          style({ transform: 'translateY(0)',    offset: 0.6 }),
          style({ transform: 'translateY(-8px)',  offset: 0.8 }),
          style({ transform: 'translateY(0)',    offset: 1 }),
        ]))
      ])
    ])
  ],
  template: `
    <div [@fadeInOut]="isVisible ? 'visible' : 'hidden'">Fade me</div>
    <div [@listAnimation]="products().length">
      <app-product-card *ngFor="let p of products()" [product]="p" />
    </div>
  `
})

Standalone vs NgModules

Know both — you'll see NgModules in older codebases and Standalone in modern ones.

Why this changed — and what you'll see in the wild Angular was released in 2016. For its first 6 years every component, pipe, and directive had to be declared inside an NgModule — a separate file that described what a group of components could see and use. Since Angular 15 (2022), components can declare their own imports directly — this is called Standalone. Every file in BlossomRays uses standalone. However, you will still encounter NgModules in many real codebases, legacy projects, and third-party libraries, so you must understand both.

Testing Basics

Angular uses Jasmine for test syntax and Karma as the test runner. Jest is also popular.

What testing actually means in Angular A unit test tests one piece of code in isolation. You're not testing the whole app — you're asking "does this service's addItem() method correctly increase the quantity when the same product is added twice?" You mock external dependencies (databases, HTTP calls) so the test is fast and deterministic.
  • TestBed — Angular's test setup utility. Creates a mini Angular environment for your test.
  • Jasmine — the test syntax library. describe() groups tests, it() is a single test, expect().toBe() is the assertion.
  • Karma — runs the tests in a browser. Often replaced with Jest in modern setups (Jest is faster and runs in Node without a browser).
A service test checks: does the class logic work correctly? A component test checks: does the rendered HTML look right and do user interactions trigger the right methods?

CLI, Build & Deploy

How to build for production and deploy to Netlify, Vercel, or a static host.

What ng build actually produces Running ng build transforms your TypeScript and HTML into a folder of plain files that any web server can serve. The output contains:
  • index.html — the single HTML file with script/style links injected automatically
  • main-[hash].js — the core Angular runtime + your shared code
  • chunk-[hash].js (multiple) — one file per lazy-loaded route. Only downloaded when that route is visited
  • styles-[hash].css — all global CSS
  • [hash] in filenames — a fingerprint of the file contents. When you deploy a new build, the hash changes, so browsers automatically download the new file instead of using a stale cached version
For Netlify: you upload this folder and set a catch-all redirect rule (/* → /index.html) so that direct URL access (e.g. someone shares a link to /products/rose-perfume) works instead of returning a 404.

NgRx — Redux State Management

The standard enterprise state library for Angular. Used in almost every large bank and enterprise Angular codebase.

StoreActions ReducersEffects Selectors
Why NgRx? Signals vs NgRx — when to use which Angular Signals (which BlossomRays uses) are great for local/shared state in smaller apps. NgRx is the choice for enterprise apps where:

// cart.reducer.ts
import { createReducer, on } from '@ngrx/store';
import * as CartActions from './cart.actions';

const initialState: CartState = { items: [] };

export const cartReducer = createReducer(
  initialState,

  on(CartActions.addToCart, (state, { item }) => {
    const existing = state.items.find(i => i.id === item.id);
    if (existing) {
      return {
        ...state,
        items: state.items.map(i =>
          i.id === item.id
            ? { ...i, quantity: i.quantity + 1 }
            : i
        )
      };
    }
    return { ...state, items: [...state.items, item] };
  }),

  on(CartActions.removeFromCart, (state, { id }) => ({
    ...state,
    items: state.items.filter(i => i.id !== id)
  })),

  on(CartActions.clearCart, state => ({
    ...state, items: []
  }))
);

🔁 NgRx Effects — Async Side Effects

What Effects are for A Reducer must be a pure function (no API calls, no side effects). When you need to call an API in response to an action, you use an Effect. It listens for a specific action, performs the async work, then dispatches a new action (success or failure) back into the store. 
// product.effects.ts
import { Actions, createEffect, ofType } from '@ngrx/effects';
import { switchMap, map, catchError } from 'rxjs/operators';

@Injectable()
export class ProductEffects {
  private actions$ = inject(Actions);
  private productService = inject(ProductService);

  loadProducts$ = createEffect(() =>
    this.actions$.pipe(
      ofType(ProductActions.loadProducts),   // listen for this action
      switchMap(() =>
        this.productService.getAll().pipe(
          map(products =>
            ProductActions.loadProductsSuccess({ products })
          ),
          catchError(error =>
            of(ProductActions.loadProductsFailure({ error }))
          )
        )
      )
    )
  );
}

OAuth 2.0 & Authentication

How modern authentication works — and how Angular implements it. Banks ask this in almost every interview.

OAuth 2.0 FlowsPKCE JWTHTTP Interceptor Supabase Auth
OAuth vs Authentication — they're not the same thing This trips up a lot of developers. OAuth 2.0 is an authorisation framework — it lets Application A access resources on Application B on behalf of a user, without the user sharing their password with Application A. For example: "Sign in with Google" — your app gets a token from Google, never the user's Google password.

Authentication ("who are you?") is handled by OpenID Connect (OIDC) — a thin identity layer built on top of OAuth 2.0. Supabase, Auth0, Cognito, and Keycloak all implement both. When you use Supabase Auth in BlossomRays, you're using OIDC for auth + OAuth 2.0 for authorization.

🔄 Authorization Code Flow + PKCE (The SPA Flow)

Why PKCE? Why not just Authorization Code flow? The original Authorization Code flow used a client secret — a password your server knows. But a browser-based SPA cannot keep secrets (anyone can open DevTools). PKCE (Proof Key for Code Exchange) replaces the client secret with a code verifier + challenge pair that is generated fresh for each login. Even if an attacker intercepts the auth code, they can't use it without the code verifier that only your app generated.

🔐 JWT — What's Inside the Token

A JWT is NOT encrypted — it is signed A JWT (JSON Web Token) has three base64-encoded parts separated by dots: header.payload.signature. Anyone can decode the header and payload (paste a JWT into jwt.io to see it). What they cannot do is forge a valid signature without the server's secret key. The resource server verifies the signature — if it's valid, it trusts the claims in the payload. 
// Decoded JWT payload — what Supabase puts in your token
{
  "sub": "uuid-of-the-user",          // subject — user ID
  "email": "user@example.com",
  "role": "authenticated",             // Supabase RLS uses this
  "aud": "authenticated",              // audience — who this token is for
  "iss": "https://xxx.supabase.co/auth/v1", // issuer
  "exp": 1722000000,                 // expiry — Unix timestamp
  "iat": 1721996400                  // issued at
}

Machine-to-machine. No user involved. Your backend service gets a token using its own client_id + client_secret. Used for internal microservices calling each other.

🛡️ How Angular Handles Tokens — The Interceptor Pattern

This is the BlossomRays auth interceptor — know this cold Instead of manually adding Authorization: Bearer ... to every HTTP call, Angular uses an HTTP interceptor — middleware that runs on every outgoing request. The interceptor reads the current token from Supabase auth, adds it to the headers, then passes the modified request through. This is the standard pattern in every Angular enterprise app. 
// auth.interceptor.ts — from BlossomRays
export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const supabase = inject(SupabaseService).client;

  return from(supabase.auth.getSession()).pipe(
    switchMap(({ data }) => {
      const token = data.session?.access_token;
      if (token) {
        // Clone the request — requests are immutable
        const authReq = req.clone({
          setHeaders: { Authorization: `Bearer ${token}` }
        });
        return next(authReq);
      }
      return next(req); // no token? pass through unauthenticated
    })
  );
};

// Register in app.config.ts:
provideHttpClient(withInterceptors([authInterceptor]))

💬 Interview Q&A — OAuth

Q: What is the difference between OAuth 2.0 and OpenID Connect?
OAuth 2.0 is an authorisation framework — it controls what your app can do (access Google Drive, read contacts). It does NOT define who the user is. OpenID Connect (OIDC) is an identity layer on top of OAuth 2.0 that adds an ID Token containing user profile claims (name, email, sub). When you need both login identity AND resource access, you use OIDC (which bundles OAuth 2.0).
Q: Why do we use short-lived access tokens instead of just one long-lived token?
If an access token is stolen, the attacker can only use it until it expires (15 minutes). A long-lived token gives attackers a much bigger window. The refresh token is long-lived but: (1) it can only be used at the auth server, not the resource server, (2) it can be revoked server-side at any time (e.g. on logout or password change), (3) each use rotates it to a new value.
Q: Where should you store tokens in a browser?
Access tokens: in memory (a JavaScript variable) — not localStorage or sessionStorage, which are vulnerable to XSS. Refresh tokens: in a secure, HttpOnly cookie — JavaScript cannot read HttpOnly cookies, so XSS attacks can't steal them. Supabase stores tokens in localStorage by default for simplicity, but enterprise apps use the cookie approach.
Q: What is PKCE and why is it needed for SPAs?
PKCE (Proof Key for Code Exchange, pronounced "pixie") solves the problem that SPAs cannot securely store a client secret (anyone can view JavaScript source). Instead of a static secret, the app generates a random code_verifier, hashes it to create a code_challenge, and sends the challenge with the auth request. When exchanging the auth code for tokens, the app sends the original verifier. The auth server hashes it and compares — only the app that started the flow can complete it.

🛍️ What Is This App?

BlossomRays is an online fragrance & lifestyle shop. Customers browse products, add them to a cart, check out via Stripe, and receive an order confirmation. There is also an admin panel for managing orders and products.

⚙️ How Angular Works — From Zero

Think of a web page as a tree of LEGO bricks. Each brick is a Component. Angular is the system that builds, connects, and updates those bricks when data changes.

🧱 Components
A component = a piece of the screen. It has HTML (template), logic (TypeScript class), and styling. Examples: NavbarComponent, ProductCardComponent, CartDrawerComponent.
💉 Services & Dependency Injection
Services hold shared logic (e.g. fetch products, manage cart). DI is Angular's way of handing a service to any component that needs it — you don't create them manually.
🔀 Router
Maps a URL path to a component. When you navigate to /products, Angular loads ProductsComponent without a full page reload.
⚡ NgRx Store + Signals
Cart state is managed by the NgRx Store (Redux pattern). CartService is a facade — it dispatches actions and exposes toSignal() bridges so all 6 components keep their existing signal-based API unchanged.

What Happens When You Open The App

1
Browser loads index.html + main.js bundle

Netlify serves the compiled Angular files. The browser downloads them.

2
Angular bootstraps the app

main.ts calls bootstrapApplication(AppComponent, appConfig). Angular starts up with the config you defined.

3
AppComponent renders the shell

It shows the AnnouncementBar, Navbar, a <router-outlet> placeholder, and Footer.

4
Router matches the URL and loads the right page

If the URL is /products, Angular downloads the ProductsComponent bundle and renders it inside <router-outlet>.

5
Services fetch data — NgRx Store manages cart state

ProductService queries Supabase. When data arrives it sets a signal. Cart actions (add/remove/update) go through store.dispatch() → Reducer → toSignal() → template update.

🌳 Component Tree — What's On Screen At Any Time

📌 The shell (Navbar, Footer, etc.) is always on screen. The <router-outlet> is the slot where the current page component renders. When you navigate, only the outlet content swaps — the shell stays.

🔄 How Data Flows Through The App

1
User visits /products

Router loads ProductsComponent lazily (separate JS chunk downloaded).

2
ngOnInit() calls ProductService.getProducts()

ProductService calls Supabase directly from the browser. Sets a signal<Product[]>.

3
Template reads the signal — DOM updates automatically

@for (product of products(); track product.id) renders a ProductCardComponent for each item with a stagger animation.

4
User clicks "Add to Cart" → NgRx dispatch

ProductCard calls CartService.addItem(). The facade dispatches addToCart({ product }) to the NgRx Store. The reducer produces a new state. toSignal(selectTotalItems) updates automatically — Navbar badge re-renders.

5
User checks out → Netlify function → Stripe → Webhook

Angular POSTs to /api/stripe/checkout. Netlify function creates Stripe session. User redirected to Stripe. On payment, Stripe sends webhook to stripe-webhook.ts which writes the order to Supabase.
