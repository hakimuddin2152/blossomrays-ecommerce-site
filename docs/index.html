BlossomRays E-Commerce App

A full-stack fragrance e-commerce platform selling car air fresheners, candles, perfumes, and accessories. Built with Angular 17 standalone components, Supabase for auth + database, Stripe for payments, and deployed on Netlify with serverless functions.

App Bootstrap

Angular 17 uses standalone bootstrap — no NgModule at all. The entry point calls bootstrapApplication() with the root component and a config object.

src/main.tsTS
import { bootstrapApplication } from '@angular/platform-browser';
import { appConfig } from './app/app.config';
import { AppComponent } from './app/app.component';

// bootstrapApplication() replaces the old platformBrowserDynamic().bootstrapModule(AppModule)
// It accepts: root component + ApplicationConfig (providers)
bootstrapApplication(AppComponent, appConfig)
  .catch((err) => console.error(err));
src/app/app.config.tsTS
import { ApplicationConfig, provideZoneChangeDetection } from '@angular/core';
import { provideRouter, withRouterConfig } from '@angular/router';
import { provideAnimations } from '@angular/platform-browser/animations';
import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    // Zone.js change detection with event coalescing (batches multiple events
    // into one CD cycle — reduces unnecessary re-renders)
    provideZoneChangeDetection({ eventCoalescing: true }),

    // Registers the router with all routes + config
    provideRouter(
      routes,
      withRouterConfig({ onSameUrlNavigation: 'reload' }),
    ),

    // Enables Angular animation engine (required for @angular/animations)
    provideAnimations(),
  ],
};
💡 Why no NgModule? Standalone mode (Angular 14+, default from 17) eliminates the NgModule indirection. Every component declares its own imports. This enables better tree-shaking and makes the dependency graph explicit at the component level.

Routing & Lazy Loading

All routes are defined in app.routes.ts. Every page component is lazy-loaded — Angular splits each route into a separate JS chunk and only downloads it when the user navigates there.

src/app/app.routes.tsTS
import { Routes } from '@angular/router';
import { authGuard } from './guards/auth.guard';
import { adminGuard } from './guards/admin.guard';

export const routes: Routes = [
  // ── Public routes ──
  {
    path: '',
    loadComponent: () =>
      import('./pages/home/home.component')
        .then((m) => m.HomeComponent),
    // dynamic import() → separate JS chunk loaded on first visit
  },
  {
    path: 'products/:slug',  // ← :slug is a route param, accessed via ActivatedRoute
    loadComponent: () =>
      import('./pages/product-detail/product-detail.component')
        .then((m) => m.ProductDetailComponent),
  },

  // ── Auth-protected routes ──
  {
    path: 'account',
    canActivate: [authGuard],   // ← guard runs before component loads
    loadComponent: () =>
      import('./pages/account/account.component')
        .then((m) => m.AccountComponent),
  },

  // ── Admin routes: requires BOTH guards ──
  {
    path: 'admin',
    canActivate: [authGuard, adminGuard],  // ← all guards must pass (AND logic)
    loadComponent: () =>
      import('./pages/admin/admin.component')
        .then((m) => m.AdminComponent),
  },

  // ── Wildcard — must be last ──
  {
    path: '**',
    loadComponent: () =>
      import('./pages/not-found/not-found.component')
        .then((m) => m.NotFoundComponent),
  },
];

Route Guards

Guards decide whether a route can be activated. This app uses functional guards (Angular 14+) — plain functions that return true | false | UrlTree. They replace the old class-based CanActivate interface.

src/app/guards/auth.guard.tsTS
import { inject } from '@angular/core';
import { Router } from '@angular/router';
import { AuthService } from '../services/auth.service';

// Functional guard — just a function, no class needed
export const authGuard = () => {
  const auth = inject(AuthService);
  const router = inject(Router);

  // auth.user() reads the signal synchronously
  if (auth.user()) return true;

  // Return UrlTree instead of router.navigate()
  // UrlTree is the modern way — router handles the redirect
  return router.createUrlTree(['/login']);
};
src/app/guards/admin.guard.tsTS
import { inject } from '@angular/core';
import { Router } from '@angular/router';
import { AuthService } from '../services/auth.service';

export const adminGuard = () => {
  const auth = inject(AuthService);
  const router = inject(Router);

  // isAdmin() checks profile().role === 'admin'
  if (auth.isAdmin()) return true;

  // Non-admins go to homepage, not login
  return router.createUrlTree(['/']);
};

Signals — Reactive State

Angular 16+ introduced Signals as a first-class reactive primitive. They are synchronous, pull-based, and integrate with Angular's change detection. This app uses signals for all local state instead of RxJS Subjects or BehaviorSubjects.

What is a Signal?

signals — mental modelTS
import { signal } from '@angular/core';

// Create a signal — like a reactive variable
const count = signal(0);

// Read value (always call as a function)
console.log(count()); // 0

// Write value
count.set(5);

// Update based on previous value (like setState with callback)
count.update(prev => prev + 1);

// In templates — no () needed, Angular unwraps automatically
// {{ count }}  ← Angular handles the subscription

Signals in AuthService

src/app/services/auth.service.tsTS
@Injectable({ providedIn: 'root' })
export class AuthService {
  // Three pieces of reactive state — all signals
  readonly user    = signal(null);    // current Supabase user
  readonly profile = signal(null); // DB profile row (has role)
  readonly loading = signal(true);                  // async init in progress

  constructor() {
    // Initial session fetch
    this.supabase.auth.getSession()
      .then(({ data }) => {
        this.user.set(data.session?.user ?? null);  // ← set() writes the signal
        if (data.session?.user) this._loadProfile(data.session.user.id);
      })
      .finally(() => { this.loading.set(false); }); // always clear loading

    // Supabase auth state changes (login, logout, token refresh)
    this.supabase.auth.onAuthStateChange((_event, session) => {
      this.user.set(session?.user ?? null);
      if (session?.user) {
        this._loadProfile(session.user.id);
      } else {
        this.profile.set(null);
      }
    });
  }

  isAdmin(): boolean {
    return this.profile()?.role === 'admin'; // ← read signal with ()
  }
}

Signals in CartService

src/app/services/cart.service.tsTS
@Injectable({ providedIn: 'root' })
export class CartService {
  // signal initialized from localStorage — persists across page refreshes
  readonly items = signal(this._load());

  addItem(product: Product, quantity = 1): void {
    this.items.update((current) => {  // ← update() for immutable updates
      const existing = current.find((i) => i.product.id === product.id);
      if (existing) {
        // Map creates new array — signals are immutable (reference change triggers re-render)
        return current.map((i) =>
          i.product.id === product.id
            ? { ...i, quantity: i.quantity + quantity }
            : i,
        );
      }
      return [...current, { product, quantity }]; // spread to new array
    });
  }

  removeItem(productId: string): void {
    // filter returns a new array — triggering change detection
    this.items.update((current) =>
      current.filter((i) => i.product.id !== productId),
    );
  }
}

Computed Signals & Effects

computed() — Derived State

A computed() creates a read-only derived signal. It only recalculates when its dependencies (other signals it reads) change. Memoized automatically.

src/app/services/cart.service.tsTS
import { signal, computed } from '@angular/core';

readonly items = signal([]);

// computed() reads items() — recalculates automatically when items changes
readonly totalItems = computed(() =>
  this.items().reduce((sum, i) => sum + i.quantity, 0),
  // If items = [{qty:2}, {qty:3}] → totalItems() = 5
);

readonly subtotal = computed(() =>
  this.items().reduce((sum, i) => sum + i.product.price * i.quantity, 0),
  // Returns cents: 1799 * 2 = 3598 → $35.98
);

// In the Navbar template:
// {{ cart.totalItems() }}  — or just {{ totalItems }} if it's a component property
// Angular tracks the dependency and re-renders when totalItems changes

effect() — Side Effects on Signal Change

An effect() runs a callback whenever any signal it reads changes. It's Angular's answer to React's useEffect — but with automatic dependency tracking.

src/app/services/cart.service.ts — localStorage persistenceTS
import { signal, computed, effect } from '@angular/core';

constructor() {
  // effect() automatically tracks which signals are read inside
  // Runs once immediately, then re-runs whenever items() changes
  effect(() => {
    try {
      // This reads items() → items becomes a dependency of this effect
      localStorage.setItem(STORAGE_KEY, JSON.stringify(this.items()));
      // Whenever items signal changes → this effect re-runs → cart is persisted
    } catch {
      // Ignore storage quota errors (private browsing, etc.)
    }
  });
}

// Equivalent in RxJS would be:
// this.items$.subscribe(items => localStorage.setItem(...))
// But effect() is automatic, no teardown/unsubscribe needed
⚠️ effect() Rules effect() must be called in an injection context (constructor or field initializer). It auto-cleans up when the component/service is destroyed. Never call effect() inside a method — only at construction time.

Pipes

Pipes transform values in templates. They are declared inline (similar to components), and pure pipes (the default) are memoized — Angular only re-runs them when the input reference changes.

src/app/pipes/format-price.pipe.tsTS
import { Pipe, PipeTransform } from '@angular/core';

@Pipe({
  name: 'formatPrice',      // name used in templates: {{ price | formatPrice }}
  standalone: true,          // standalone pipe — import directly into components
  pure: true,                // DEFAULT — memoized, re-runs only when input changes
  // pure: false             // impure — re-runs every CD cycle (expensive, avoid)
})
export class FormatPricePipe implements PipeTransform {
  // transform(value, ...args): receives the piped value + optional arguments
  transform(cents: number): string {
    // Intl.NumberFormat for locale-aware currency formatting
    return new Intl.NumberFormat('en-CA', {
      style: 'currency',
      currency: 'CAD',
    }).format(cents / 100);
    // 1799 → "CA$17.99"
  }
}

RxJS Operators + async pipe

The navbar search demonstrates a full RxJS pipeline: a Subject bridges the DOM event world with the reactive world, operator pipes transform the stream, and the async pipe subscribes in the template.

src/app/components/layout/navbar.component.ts — search pipelineTS
import { Subject, Observable, of, from } from 'rxjs';
import { debounceTime, distinctUntilChanged, switchMap, map, startWith } from 'rxjs/operators';

// Subject: both Observable (can subscribe) AND Observer (can call .next())
// Acts as the bridge between user input → RxJS pipeline
private readonly search$ = new Subject();

// Observable derived from the Subject via pipe operators
readonly searchSuggestions$: Observable = this.search$.pipe(

  startWith(''),           // emit '' immediately so Observable is warm from the start

  debounceTime(300),       // wait 300ms after LAST emission — no request per keypress

  distinctUntilChanged(),  // skip if value didn't change since last emission

  switchMap((query) => {   // cancel pending inner Observable when new query arrives
    if (query.trim().length < 2) return of([]); // of() creates Observable from value

    // from() converts Promise → Observable
    return from(this.productService.getProducts()).pipe(
      map((products) =>             // transform each emitted array
        products
          .filter(p => p.name.toLowerCase().includes(query.toLowerCase()))
          .slice(0, this.config.maxSearchSuggestions),
      ),
    );
  }),
);

// Called on (input) event — pushes value into the Subject
onSearchInput(event: Event): void {
  const value = (event.target as HTMLInputElement).value;
  this.search$.next(value);   // .next() feeds the Subject
}

// HttpInterceptorFn — plain function, no class needed (Angular 15+)
export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const supabase = inject(SupabaseService);

  // from() converts the Promise to Observable for use in pipe
  return from(supabase.client.auth.getSession()).pipe(
    switchMap(({ data }) => {
      const token = data.session?.access_token;
      if (!token) return next(req); // no session — pass through unchanged

      // HttpRequest is IMMUTABLE — must clone() to modify
      const authReq = req.clone({
        setHeaders: { Authorization: `Bearer ${token}` },
      });

      return next(authReq); // pass modified request downstream
    }),
  );
};

function passwordMatchValidator(group: AbstractControl): ValidationErrors | null {
  const password        = group.get('password')?.value;
  const confirmPassword = group.get('confirm_password')?.value;

  if (!password || !confirmPassword) return null; // don't flag while typing

  return password === confirmPassword
    ? null                          // valid — return null

import { Injectable } from '@angular/core';
import { createClient, SupabaseClient } from '@supabase/supabase-js';
import { environment } from '../environments/environment';

// Custom lock implementation: Supabase uses navigator.locks to serialize
// token refreshes across browser tabs. When a second tab tries to acquire
// the lock it throws an unhandled rejection. This noop replaces it with a
// simple "just run the function" — correct for single-tab, silences the error.
function noopLock(
  _name: string,
  _opts: { mode: string },
  fn: () => Promise,
): Promise {
  return fn(); // skip locking, just execute
}

@Injectable({ providedIn: 'root' })
export class SupabaseService {
  private _client: SupabaseClient | null = null;

  // Lazy getter — client is only created on first access
  get client(): SupabaseClient {
    if (!this._client) {
      const { supabaseUrl, supabaseAnonKey } = environment;

      if (!supabaseUrl || supabaseUrl === 'YOUR_SUPABASE_URL') {
        // GRACEFUL DEGRADATION: app still renders if credentials aren't set
        // Uses a placeholder URL so Supabase SDK doesn't throw synchronously
        console.warn('[SupabaseService] Credentials not configured');
        this._client = createClient('https://placeholder.supabase.co', 'placeholder', {
          auth: { lock: noopLock },
        });
      } else {
        this._client = createClient(supabaseUrl, supabaseAnonKey, {
          auth: { lock: noopLock },
        });
      }
    }
    return this._client;
  }
}

@Injectable({ providedIn: 'root' })
export class AuthService {
  private readonly supabase = inject(SupabaseService).client;
  private readonly router = inject(Router);

  // Public reactive state — components read these signals
  readonly user    = signal(null);
  readonly profile = signal(null);
  readonly loading = signal(true);   // true during initial session check

  constructor() {
    // Check existing session (e.g., user refreshes the page)
    this.supabase.auth.getSession()
      .then(({ data }) => {
        this.user.set(data.session?.user ?? null);
        if (data.session?.user) this._loadProfile(data.session.user.id);
      })
      .catch(() => { /* network error or missing credentials — stay logged out */ })
      .finally(() => { this.loading.set(false); });

    // Subscribe to Supabase auth events:
    // SIGNED_IN, SIGNED_OUT, TOKEN_REFRESHED, USER_UPDATED
    this.supabase.auth.onAuthStateChange((_event, session) => {
      this.user.set(session?.user ?? null);
      if (session?.user) {
        this._loadProfile(session.user.id);
      } else {
        this.profile.set(null);
      }
    });
  }

  async signIn(email: string, password: string): Promise {
    const { error } = await this.supabase.auth.signInWithPassword({ email, password });
    if (error) return 'Invalid email or password. Please try again.';
    return null; // null = success
  }

  async signUp(email: string, password: string, fullName: string): Promise {
    const { error } = await this.supabase.auth.signUp({
      email, password,
      options: { data: { full_name: fullName } }, // stored in auth.users.raw_user_meta_data
    });
    if (error) return error.message;
    return null;
  }

  async signOut(): Promise {
    await this.supabase.auth.signOut();
    this.router.navigate(['/']); // redirect to home on logout
  }

  isAdmin(): boolean {
    return this.profile()?.role === 'admin';
  }

  // Private — loads the user's profile row from public.profiles table
  private async _loadProfile(userId: string): Promise {
    const { data } = await this.supabase
      .from('profiles')
      .select('*')
      .eq('id', userId)
      .maybeSingle(); // returns null if not found (vs .single() which throws)
    this.profile.set(data ?? null);
  }
}

CartService

Manages the shopping cart with signal-based state and automatic localStorage persistence via effect(). No backend calls — pure client-side state.

src/app/services/cart.service.ts (complete)TS
const STORAGE_KEY = 'blossomrays-cart';

@Injectable({ providedIn: 'root' })
export class CartService {
  // Initialize signal from localStorage — restores cart across page refreshes
  readonly items = signal(this._load());

  // Derived signals — auto-update when items changes
  readonly totalItems = computed(() =>
    this.items().reduce((sum, i) => sum + i.quantity, 0),
  );

  readonly subtotal = computed(() =>
    this.items().reduce((sum, i) => sum + i.product.price * i.quantity, 0),
  );

  constructor() {
    // Side effect: persist to localStorage on every items change
    effect(() => {
      try {
        localStorage.setItem(STORAGE_KEY, JSON.stringify(this.items()));
      } catch { /* quota exceeded in private browsing */ }
    });
  }

  addItem(product: Product, quantity = 1): void {
    this.items.update((current) => {
      const existing = current.find((i) => i.product.id === product.id);
      if (existing) {
        // Always return a NEW array — signals detect changes by reference
        return current.map((i) =>
          i.product.id === product.id
            ? { ...i, quantity: i.quantity + quantity }
            : i,
        );
      }
      return [...current, { product, quantity }];
    });
  }

  removeItem(productId: string): void {
    this.items.update((current) =>
      current.filter((i) => i.product.id !== productId),
    );
  }

  updateQuantity(productId: string, quantity: number): void {
    if (quantity <= 0) {
      this.removeItem(productId); // auto-remove when quantity goes to 0
      return;
    }
    this.items.update((current) =>
      current.map((i) =>
        i.product.id === productId ? { ...i, quantity } : i,
      ),
    );
  }

  clearCart(): void {
    this.items.set([]); // called after successful order placement
  }

  // Private: safely parse localStorage
  private _load(): CartItem[] {
    try {
      const raw = localStorage.getItem(STORAGE_KEY);
      if (!raw) return [];
      const parsed = JSON.parse(raw);
      return Array.isArray(parsed) ? (parsed as CartItem[]) : [];
    } catch {
      return []; // JSON.parse error or localStorage unavailable
    }
  }
}

Stripe Webhook Function

Receives Stripe events after payment completes. Creates order records in the database. Uses signature verification and idempotency checks.

netlify/functions/stripe-webhook.tsTS
export const handler: Handler = async (event: HandlerEvent) => {
  // 1. SIGNATURE VERIFICATION — prevents fake webhook calls
  //    Stripe signs every webhook with STRIPE_WEBHOOK_SECRET
  //    If sig doesn't match → reject immediately
  const sig = event.headers['stripe-signature'];
  let stripeEvent: Stripe.Event;
  try {
    stripeEvent = stripe.webhooks.constructEvent(
      event.body ?? '',
      sig,
      process.env.STRIPE_WEBHOOK_SECRET,
    );
  } catch (err) {
    return { statusCode: 400, body: JSON.stringify({ error: 'Invalid signature' }) };
  }

  // 2. Only handle successful checkout events
  if (stripeEvent.type !== 'checkout.session.completed') {
    return { statusCode: 200, body: JSON.stringify({ received: true }) };
  }

  const session = stripeEvent.data.object as Stripe.Checkout.Session;

  // 3. IDEMPOTENCY CHECK — webhooks can fire more than once
  //    If we already processed this session ID, skip and return 200
  const { data: existing } = await supabase
    .from('orders')
    .select('id')
    .eq('stripe_session_id', session.id)
    .single();

  if (existing) {
    return { statusCode: 200, body: JSON.stringify({ skipped: 'duplicate' }) };
  }

  // 4. Fetch actual line items from Stripe (prices already validated on checkout)
  const lineItems = await stripe.checkout.sessions.listLineItems(session.id, {
    expand: ['data.price.product'],
  });

  // 5. Write order to Supabase (using service_role key — RLS bypassed)
  const { data: order } = await supabase
    .from('orders')
    .insert({
      stripe_session_id: session.id,
      email,
      status: 'paid',
      shipping_address: shippingAddress, // JSONB column
      subtotal, shipping: SHIPPING_COST, total,
    })
    .select('id')
    .single();

  // 6. Write order_items
  await supabase.from('order_items').insert(orderItems.map(i => ({
    order_id: order.id,
    product_id: i.product_id,
    quantity: i.quantity,
    unit_price: i.unit_price,
  })));

  return { statusCode: 200, body: JSON.stringify({ received: true, orderId: order.id }) };
};

Interview Q&A Cheat Sheet

Angular Questions

Q: What is the difference between a standalone component and one declared in NgModule?

A: A standalone component (standalone: true) declares its own imports in the @Component decorator instead of relying on a shared NgModule. This makes dependencies explicit, enables better tree-shaking, eliminates NgModule boilerplate, and allows components to be lazy-loaded directly via loadComponent(). Every component in this app is standalone.

Q: What are Angular Signals and how are they different from RxJS?

A: Signals are synchronous reactive primitives — signal() creates a writable value, computed() creates derived values, and effect() handles side effects. Unlike RxJS Observables, signals are always synchronous, don't require subscriptions/unsubscriptions, and integrate natively with Angular's change detection. They're best for local synchronous state. RxJS is still superior for async streams, HTTP, or complex event pipelines. In this app, CartService uses signals for cart state and effect() to auto-persist to localStorage.

Q: How does lazy loading work with standalone components?

A: Each route uses loadComponent: () => import('./path').then(m => m.ComponentClass). The dynamic import() creates a separate webpack chunk. The browser only downloads that chunk when the route is first activated. Guards run before the chunk is even fetched — if they fail, the JS is never downloaded.

Q: What is inject() and when do you use it?

A: inject() is a function that retrieves a dependency from Angular's DI container. It must be called in an injection context (field initializers, constructor, or runInInjectionContext()). It replaces constructor parameter injection and is cleaner in standalone components. Functional guards use inject() since they're not classes.

Q: What is the difference between pure and impure pipes?

A: A pure pipe (default) is memoized — Angular only re-runs transform() when the input reference changes. An impure pipe (pure: false) re-runs on every change detection cycle regardless of input, which is expensive. FormatPricePipe in this app is pure — it transforms cents to a formatted currency string and only recalculates when the price value changes.

Q: Explain the route guard setup in this app.

A: The app uses two functional guards. authGuard checks AuthService.user() signal — if null, returns router.createUrlTree(['/login']). adminGuard checks auth.isAdmin() which reads profile().role === 'admin'. Admin routes use canActivate: [authGuard, adminGuard] — all guards must return true (AND logic). If authGuard fails, the router short-circuits and adminGuard never runs.

Q: How does change detection work with Signals vs Zone.js?

A: Classic Angular uses Zone.js to monkey-patch async APIs and trigger change detection after any async operation. With Signals, Angular knows exactly which component depends on which signal — when a signal changes, only those components re-render (fine-grained reactivity). This app still uses Zone.js (provideZoneChangeDetection({ eventCoalescing: true })) but the signals work alongside it. The future is zoneless Angular where Zone.js is removed entirely.

Q: What is an InjectionToken and when do you use it instead of a class service?

A: InjectionToken is used when the value you want to provide is not a class — e.g. a config object, a string, a number, or a factory function. It's strongly typed via the generic InjectionToken<T> and avoids name collision since it's an object reference, not a string. In this app, APP_CONFIG holds shipping thresholds and currency — injected in checkout to replace magic numbers, and easily overridden in tests with a mock value.

Q: What is a custom directive and what are @HostListener / @Output used for inside one?

A: A directive adds behaviour to a DOM element without a template. @HostListener('document:click', ['$event.target']) listens to every click on the document — the host element is identified via ElementRef.nativeElement. If the click lands outside (!el.nativeElement.contains(target)), @Output() clickedOutside emits. The parent binds it with (clickedOutside)="mobileOpen.set(false)". Angular automatically removes the listener on directive destroy — no manual cleanup.

Q: When should you use @defer vs lazy-loaded routes?

A: Lazy routes are route-level — the entire page component chunk is deferred until navigation. @defer is template-level — parts of a single page can be deferred independently. Use @defer (on viewport) for below-fold sections (testimonials, newsletter) that may never be reached. Use @defer (on interaction) for modals or dialogs. Critical above-fold content stays in the main bundle. Both together give maximum bundle splitting.

Q: Explain the RxJS operators used in the navbar search pipeline.

A: A Subject<string> receives raw keystrokes via .next(value). debounceTime(300) waits 300ms after the last keystroke — prevents a network call per keypress. distinctUntilChanged() drops the emission if the value hasn't changed. switchMap cancels the previous inner Observable when a new query arrives — critical for search to prevent stale results racing. from(promise) converts the product fetch Promise into an Observable. The async pipe in the template subscribes and auto-unsubscribes.

Q: What is the difference between switchMap, mergeMap, and exhaustMap?

A: switchMap cancels the previous inner Observable when a new outer value arrives — use for search (always want the latest). mergeMap runs all inner Observables concurrently, no cancellation — use for parallel independent requests. exhaustMap ignores new outer values while the current inner Observable is still active — perfect for form submit (prevents double-submit).

Q: What is an HTTP Interceptor and how does it work?

A: An interceptor is middleware in Angular's HttpClient pipeline. Every HTTP request/response passes through registered interceptors in order. The functional form (HttpInterceptorFn) is a function (req, next) => Observable<HttpEvent>. req is immutable — you must call req.clone({...}) to modify it. The authInterceptor here reads the Supabase session token, clones the request with an Authorization: Bearer header, then passes it to next(authReq). Registered via provideHttpClient(withInterceptors([...])).

Q: What is a cross-field validator vs a control-level validator?

A: A control-level validator (Validators.required, Validators.minLength) applies to a single FormControl and only sees that control's value. A cross-field validator is applied to the FormGroup (second arg of fb.group()) and receives the whole group — enabling comparison between controls. Errors from group-level validators live on form.errors, not on form.get('field').errors. The passwordMatchValidator compares password vs confirm_password and returns { passwordMismatch: true } if they differ.

Architecture Questions

Q: Why are prices in cents (integers) instead of decimals?

A: Floating-point arithmetic is imprecise — 0.1 + 0.2 !== 0.3 in JavaScript. Storing money as integers (cents) avoids rounding errors. All arithmetic is done on integers, and only formatting (display) converts to decimal. Stripe also uses cents natively.

Q: Why use Netlify Functions instead of a dedicated backend?

A: The app has minimal backend requirements — just two critical operations (create Stripe session, receive Stripe webhook). Serverless functions eliminate server maintenance, scale to zero cost when idle, and are co-located with the frontend in the same repo and deployment pipeline. A dedicated Node/Express backend would be over-engineering for this use case.

Q: How does the app prevent a user from manipulating prices at checkout?

A: The Angular checkout page sends cart items to the serverless function, but the function ignores the client-submitted price. It fetches prices from Supabase (or the TRUSTED_PRODUCTS server-side map) and creates the Stripe session with those authoritative prices. Even if a user edits the network request in devtools to change price: 1, the actual charge will be 1799 (the real price).

Q: What is Row Level Security and why is it important?

A: RLS is a PostgreSQL feature that filters rows based on the current database user's identity. In Supabase, it uses the JWT token to identify the user. With RLS enabled on orders, a user can only SELECT rows where email = their email — even if they call the Supabase API directly. This is database-level authorization, not just application-level. Without RLS, a user could query all orders by changing the request.

Q: What is idempotency and why does the webhook implement it?

A: Idempotency means an operation produces the same result no matter how many times it's called. Stripe may send a webhook event more than once (network retries, failures). Without idempotency, the same payment could create multiple orders. The webhook checks if orders.stripe_session_id already exists — if so, it skips insertion and returns 200 (confirming receipt to Stripe).
