1 What Is This App?

2 How Angular Works — From Zero

Think of a web page as a tree of LEGO bricks. Each brick is a Component. Angular is the system that builds, connects, and updates those bricks when data changes.

2.1 — The Three Big Ideas

🧱
Components

A component = a piece of the screen. It has HTML (template), logic (TypeScript class), and styling. Examples: NavbarComponent, ProductCardComponent, CartDrawerComponent.

💉
Services & Dependency Injection

Services hold shared logic (e.g. fetch products, manage cart). Dependency Injection (DI) is Angular's way of handing a service to any component that needs it — you don't create them manually.

🔀
Router

The Router maps a URL path to a component. When you navigate to /products, Angular loads ProductsComponent into the page without a full page reload.

⚡
Signals (Reactive State)

A signal is a variable that Angular watches. When the signal changes, Angular automatically updates the parts of the screen that use it — no manual DOM manipulation needed.

2.2 — What Happens When You Open The App

1
Browser loads index.html + main.js bundle

Netlify serves the compiled Angular files. The browser downloads them.

2
Angular bootstraps the app

main.ts calls bootstrapApplication(AppComponent, appConfig). Angular starts up with the config you defined.

3
AppComponent renders the shell

It shows the AnnouncementBar, Navbar, a <router-outlet> placeholder, and Footer.

4
Router matches the URL and loads the right page

If the URL is /products, Angular downloads the ProductsComponent bundle and renders it inside the <router-outlet>.

5
Services fetch data, Signals update the UI

ProductService queries Supabase. When data arrives it sets a signal. The template automatically re-renders with the new products list.

2.3 — A Component Explained Line by Line

// This is a TypeScript file. The @ symbol means "decorator" — metadata Angular reads.

@Component({
  selector: 'app-product-card',  // the HTML tag: <app-product-card>
  standalone: true,              // no NgModule needed — modern Angular
  imports: [RouterLink, CommonModule], // other components/directives this one uses
  template: `                        // the HTML for this component
    <div>
      <h2>{{ product.name }}</h2>  // {{ }} = display a value
      <p [style.color]="'red'">    // [ ] = bind a property
      <button (click)="addToCart()"> // ( ) = listen to an event
    </div>
  `
})
export class ProductCardComponent {
  @Input() product!: Product;    // data passed IN from parent component
  @Output() cartAdded = new EventEmitter<Product>(); // event sent OUT to parent

  private readonly cart = inject(CartService); // ask Angular for CartService

  addToCart() {
    this.cart.addItem(this.product);
    this.cartAdded.emit(this.product); // tell the parent it happened
  }
}
💡 Key insight: Every component is just a TypeScript class with an @Component decorator that adds the HTML template. That's it.

4 10 Key Angular Concepts Used In This App

① Signals — Reactive State

A signal is a value that Angular tracks. When the value changes, any part of the screen using it updates automatically. Think of it like a "smart variable".

// In CartService (cart.service.ts)
readonly items      = signal<CartItem[]>([]);          // writable state
readonly totalItems = computed(() => items().reduce(...)); // auto-derived

effect(() => {                                           // side-effect
  localStorage.setItem('cart', JSON.stringify(items()));
});

// When items() changes:
//  1. totalItems() automatically recalculates
//  2. effect() re-runs and saves to localStorage
//  3. Any template showing {{ totalItems() }} updates instantly

② Dependency Injection — Getting Services

Instead of writing new CartService(), you tell Angular "I need CartService" and Angular gives you the one shared instance. This is called Dependency Injection.

// OLD way (not used here) — bad, creates a new instance each time
const cart = new CartService();

// MODERN Angular way — inject() inside a class body
private readonly cart = inject(CartService);

// Also works in plain functions (guards, interceptors)
export const authGuard = () => {
  const auth = inject(AuthService); // Angular hands you the singleton
  return auth.user() ? true : router.createUrlTree(['/login']);
};
🎯 Interview line: "inject() is the modern alternative to constructor injection. It works in any injection context — class fields, constructors, or functional guards and interceptors."

③ Lazy-Loaded Routing

Every route in this app is lazy-loaded — Angular only downloads the code for a page when the user actually navigates there. This keeps the initial app bundle small and fast.

// app.routes.ts — all routes are lazy
{
  path: 'products',
  loadComponent: () =>
    import('./pages/products/products.component')
      .then(m => m.ProductsComponent),
      // ↑ Dynamic import = separate bundle = downloaded only on first visit
}

④ Route Guards — Security Checkpoints

Before Angular loads a protected page, it runs the guard function. If the guard returns true, the page loads. If it returns a UrlTree, the user is redirected instead.

⑤ HTTP Interceptor — Middleware for Every Request

Every time the Angular app calls the Netlify API, the authInterceptor runs first. It reads the Supabase JWT and attaches it as an Authorization: Bearer <token> header automatically.

// interceptors/auth.interceptor.ts
// This runs for EVERY HttpClient request, before it leaves the app.
export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const supabase = inject(SupabaseService);

  return from(supabase.client.auth.getSession()).pipe(
    switchMap(({ data }) => {
      const token = data.session?.access_token;
      if (!token) return next(req); // no login — pass through unchanged

      const authReq = req.clone({   // ← must clone! HttpRequest is IMMUTABLE
        setHeaders: { Authorization: `Bearer ${token}` }
      });
      return next(authReq);          // pass modified clone to next handler
    })
  );
};

⑥ Reactive Forms — With Validators

The checkout and register pages use Reactive Forms. The form model is defined in TypeScript, giving you full control to validate, enable/disable fields, and add custom rules.

// register.component.ts — custom cross-field validator
function passwordMatchValidator(group: AbstractControl): ValidationErrors | null {
  const pw  = group.get('password')?.value;
  const cpw = group.get('confirm_password')?.value;
  return pw === cpw ? null : { passwordMismatch: true };
  // null = valid | object = error
}

// In the component:
form = fb.group({
  full_name: ['', Validators.required],
  email:     ['', [Validators.required, Validators.email]],
  password:  ['', Validators.minLength(8)],
  confirm_password: [''],
}, { validators: passwordMatchValidator });

⑦ DestroyRef + takeUntilDestroyed — No Memory Leaks

When a component is destroyed (user navigates away), any running subscriptions must be cleaned up. takeUntilDestroyed does this automatically.

// products.component.ts
private readonly destroyRef = inject(DestroyRef);

ngOnInit() {
  this.route.queryParams
    .pipe(takeUntilDestroyed(this.destroyRef)) // ← unsubscribes when component destroys
    .subscribe(params => {
      this.selectedCategory.set(params['category'] ?? '');
    });
}

⑨ Angular Animations — Stagger Effect on Products

On the Products page, when the product list loads, each card animates in with a 40ms delay between each one (stagger). This uses @angular/animations.

// products.component.ts — declared in @Component metadata
animations: [
  trigger('listAnimation', [
    transition('* => *', [          // any value change fires this
      query(':enter', [            // select elements being added
        style({ opacity: 0, transform: 'translateY(16px)' }),
        stagger(40, [             // 40ms gap between each card
          animate('300ms ease-out', style({ opacity: 1, transform: 'translateY(0)' }))
        ])
      ], { optional: true })
    ])
  ])
]
// In template: <div [@listAnimation]="products().length">

⑩ Standalone Architecture + InjectionToken

Standalone means no NgModule — every component declares its own imports. InjectionToken is used to inject non-class values (like config objects) into the DI system.

// tokens/app-config.token.ts
export const APP_CONFIG = new InjectionToken<AppConfig>('app.config', {
  factory: () => ({ apiUrl: '/api', maxCartItems: 99 })
  // ↑ default value — no need to register in app.config.ts
});

// Usage anywhere:
const config = inject(APP_CONFIG);
5 How Data Flows Through The App

This shows what happens from the moment a user visits /products to seeing the product list on screen.

1
User visits /products

Router matches the path, downloads the products bundle, creates ProductsComponent.

2
ngOnInit() runs

Component lifecycle starts. loadProducts() is called. A loading signal is set to true — spinner appears.

3
ProductService.getProducts() calls Supabase

The service sends a SQL query via the Supabase JS SDK. This is a direct browser→Supabase call (no Netlify function needed for reads).

4
Supabase returns JSON data

The list of products arrives as a JavaScript array.

5
Signals update

products.set(data) and loading.set(false). Angular detects the signal changes.

6
Template re-renders automatically

Spinner hides. Product cards appear with the stagger animation. Each ProductCardComponent receives its product via @Input().

6 Authentication Flow

Authentication is handled by Supabase Auth. The Angular app never stores passwords — Supabase handles that. Here's the full login journey:

1
User fills in email + password on /login

Reactive Form with FormBuilder, Validators.email, and Validators.required.

2
AuthService.signIn() calls Supabase

supabase.auth.signInWithPassword({ email, password }). Supabase verifies credentials and returns a JWT session.

3
onAuthStateChange fires

Supabase fires this event in AuthService constructor. user.set(session.user) updates the signal. Any component reading auth.user() re-renders instantly.

4
Profile is loaded from Supabase DB

_loadProfile(userId) queries the profiles table. The role field ('user' or 'admin') is stored in profile signal.

5
authGuard now lets the user through

Because auth.user() is now truthy, the guard returns true for /account. The adminGuard additionally checks profile().role === 'admin'.

6
JWT attaches to all API calls automatically

The authInterceptor reads the Supabase session and appends Authorization: Bearer <token> to every HttpClient request. Netlify functions verify this token.

8 Interview Questions & Plain-English Answers

These are questions a Senior Angular architect would be expected to answer. The answers are written simply so you can understand them and then say them in your own words.

Q1 What is Angular and how is it different from plain JavaScript?

Angular is a framework — it gives you a structured way to build complex web apps. Plain JavaScript is just a language; you'd have to build everything yourself (routing, state management, form validation).

Angular gives you: a component system (building blocks), a router (page navigation), a DI system (sharing services), a forms library, an HTTP client, and change detection (auto-update the screen when data changes).

Q2 What is a Component and what are its key parts?

A component is a reusable piece of UI. It has three parts:

  • Template — the HTML, with Angular binding syntax ({{ }}, [ ], ( ))
  • Class — the TypeScript logic (properties, methods, lifecycle hooks)
  • Metadata — the @Component decorator that links the two and defines the selector
Q3 What are Signals? Why did you use them instead of RxJS/NgRx?

Signals are Angular's built-in reactive state system. A signal is a value that Angular watches. When you call .set() or .update() on it, anything in the template that reads it automatically re-renders.

I used signals because this app's state is local and simple — cart items, loading flags, form state. NgRx is for large-scale apps with complex shared state between many parts. RxJS is powerful for streams of events over time. Signals are the right tool when you just need "a variable that updates the screen".

signal() = writable. computed() = read-only derived. effect() = side-effect that auto-runs when signals change.

Q4 What is Dependency Injection? Why is it useful?

DI is Angular's way of sharing instances of services across the app. Instead of every component creating its own new CartService(), Angular creates one instance and hands it to everyone who asks for it via inject(CartService).

Benefits: (1) shared state — all components see the same cart. (2) Testability — you can swap a real service for a fake one in tests. (3) Separation of concerns — components don't need to know how to create their dependencies.

Q6 What is an HTTP Interceptor and what does it do in this app?

An interceptor is middleware for HTTP calls. Every time the app makes an API request via HttpClient, the interceptor runs first.

In this app, the authInterceptor reads the Supabase JWT from the session and appends Authorization: Bearer <token> to every request. The Netlify functions then verify that token to authenticate the user — without every API call having to manually attach the header.

Key rule: HttpRequest is immutable. You must call req.clone() to modify it.

Q7 What is Lazy Loading and why did you use it?

Lazy loading means not downloading a page's code until the user navigates there. Using loadComponent: () => import('...') in the route config tells Angular to create a separate JS bundle for each page.

Without lazy loading, the browser would download the admin dashboard code even for users who never visit it. With lazy loading, the initial bundle is small (fast first load), and code is downloaded on-demand.

Q8 What is a Route Guard? How did you implement admin protection?

A guard is a function that runs before a route loads. It returns true (allow), false (block), or a UrlTree (redirect).

Admin routes use two guards stacked: canActivate: [authGuard, adminGuard]. authGuard checks the user is logged in. adminGuard checks the user's role in the profiles table is 'admin'. If either fails, the user is redirected to login or home.

Q9 Why use DestroyRef and takeUntilDestroyed?

When a component subscribes to an Observable (like route params), that subscription stays active even after the user navigates away — a memory leak. Over time, hundreds of lingering subscriptions degrade performance.

takeUntilDestroyed(destroyRef) automatically cancels the subscription when the component is destroyed. DestroyRef is Angular's way of exposing the "component being destroyed" event as an injectable object, so you can use it inside services or functions too.

Q10 Why is the Stripe secret key on the server, not in Angular?

The Angular app runs inside the user's browser. Anything in the browser can be read by the user (or a malicious script). If the Stripe secret key was in the Angular code, anyone could open DevTools → Sources, find the key, and use it to charge arbitrary credit cards.

The Netlify function runs server-side — users never see its source code. The Angular app sends the cart contents to the function, which uses the secret key to create a Stripe Checkout session and returns only a safe, time-limited payment URL to the browser.

Q11 What is Standalone architecture? What problem does it solve?

Before Angular 15, every component had to belong to an NgModule — a separate file declaring what the component can use. This created indirection: you'd have to look at the module file to understand a component's dependencies.

Standalone components declare their own imports: [...] array directly. Benefits: (1) easier to understand — one file = one component = all its dependencies visible. (2) More portable. (3) Better tree-shaking (unused code gets stripped). This is now the recommended approach in Angular 17+.

Q12 Walk me through the checkout flow from the user's perspective vs what happens in code.

User sees: Fills in name + email → clicks "Pay with Stripe" → is taken to Stripe's hosted payment page → enters card → redirected back to /order-confirmation.

In code: CheckoutComponent validates the reactive form → calls HttpClient.post('/api/stripe/checkout', cartItems) → authInterceptor attaches JWT → Netlify function verifies token, calls Stripe API with secret key, returns { url } → Angular sets window.location.href = url → user pays on Stripe → Stripe calls the webhook function → webhook writes the order to Supabase → Angular polls /api/orders/:id until status = 'paid'.

9 Quick Reference Cheatsheet
signal(value)
Create reactive state. Read: items(). Write: items.set([]), items.update(v => [...])
computed(() => ...)
Auto-derived signal. Re-runs only when its signal dependencies change. Read-only.
effect(() => ...)
Side-effect that re-runs when its signals change. Used to sync to localStorage here.
inject(Service)
Get a service from Angular's DI. Works in class bodies, constructors, guards, interceptors.
@Input()
Receive data from a parent component via property binding: [product]="p"
@Output()
Emit events to a parent component: cartAdded.emit(product) → (cartAdded)="fn($event)"
loadComponent: () => import(...)
Lazy load a route component — creates a separate JS bundle, downloaded on first visit.
canActivate: [guard]
Run a guard before loading a route. Return true/false/UrlTree (redirect).
HttpInterceptorFn
Middleware for every HttpClient request. Clone request to modify it. Must return Observable.
FormBuilder.group()
Build a reactive form with controls and validators. Access: form.get('email').
takeUntilDestroyed(destroyRef)
Auto-cancel Observable subscription when component destroys. Prevents memory leaks.
standalone: true
Component manages its own imports array. No NgModule wrapper needed.
ngOnInit()
Lifecycle hook. Runs after Angular sets @Input values. Use for data fetching.
ngOnDestroy()
Lifecycle hook. Runs when component is removed. Use for cleanup (or use DestroyRef instead).
router-outlet
Placeholder in the template where the active route's component renders.
InjectionToken
Typed DI token for non-class values (config objects, strings). Avoids name collisions.
